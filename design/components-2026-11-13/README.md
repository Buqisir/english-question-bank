## 二、方法（取证只用原始材料）

1. **源码**（`static.mjs`）：TypeScript 语法树读 `app/src` 里每个 `.tsx` 的原生 JSX 元素（类名、role、aria-*、disabled、onClick、包着它的条件），postcss 语法树读每条 CSS 规则；统计手写的影子、圆角、色值、字号（定义处 tokens.css、`:root` 不算手写）。行为（撤销、计时、Esc、焦点去向、弹层钩子、读屏播报、加载占位）也从语法树里找。
2. **页面实拍**（`rig.mjs` + `scenarios.mjs` + `render.mjs` + `collect.mjs`）：起一个本地网站（临时数据库 + 固定测试数据 + owner 账号），Vite 插件只在清点时给每个原生 JSX 元素加 `data-inv="文件:行:列"`，所以页面上每个元素都能对回源码那一行。Playwright 按固定顺序走页面状态，1440 宽取实算样式、截图、强制悬停 / 焦点 / 按下（CDP `CSS.forcePseudoState`）、跑 axe-core 4.14.0；390 宽在全新网站上再走一遍看窄屏变化。
3. **归类**（`analyze.mjs`）：先按实算样子和 role 归进九类（规则有序、写在脚本里），再按「老师在这里要干什么」分工作（先看老师看得到的字和读屏名字，认不出才看点击处理函数）。同一类里按样式签名精确分组，再把差一点点的按容差并成一种并记为走样：色差 ΔE76 ≤ 3、圆角 ±1px、字号 ±0.5px、高度 ±2px、内边距 ±2px、影子 ±1px。悬停、焦点、按下、禁用、选中的实例不单独成种，算在静止样子的那一种上。
4. **对照**：DESIGN.md §4 四档影子（`--elev-*`）、§5 圆角家族 {0, 4, 8, 12, 16, 胶囊, 50%}、色阶 token；WCAG 2.2 文字对比度 4.5 : 1、点击区域 24×24（2.5.8）；焦点可见（强制 `:focus-visible` 前后有没有变化）；读屏名字；axe 违规。DESIGN.md、BRAND.md、质感规范只拿来对照，不当证据。
5. **来历**：每种变体的主类名用 `git log -S` 找第一次出现的提交；在 `design/`、`docs/` 里找提到它的方案文档和 Owner 原话（「有意」只在查得到 Owner 决定时标）；找锁着它的 `scripts/verify-*.mjs`。
6. **抽构件难易**（机械打分）：类名随状态拼接、所在文件超过 800 行、点击处理写在行内超过一半，三条占 0 条 = 易，1 条 = 中，2 条以上 = 难。

### 2. 同一件事、几种样子（主线上的，原始数据可复查）

- **顶栏同一个按钮四种样子**（`AppTopbar.tsx:187` 等）：首页类顶栏 14px / 高 36，工作区顶栏 13px / 高 28，听写页字重 400；草稿卷打开菜单时「生词本」又变成墨色（原因没查，可能是悬停高亮没被认出来）。
- **「返回找题」五种写法**：顶栏 `topbar-back`（13px 灰）、听写页同一个元素变成 16px / 400 墨色、详情页 `back-button`（高 18）、卷面出错页带描边的 `paper-browse-error-back`、空状态里的绿色「去找题」。
- **「更多 / 展开」6 种**：「⋯」按钮圆角 8 和 4 两套（`concierge-group-row-icon` 对比 `draft-group-actions-menu-trigger`），高 28 和 36 两档。
- **菜单和对话框的圆角两套**（都是白底、16px、`--elev-3`）：题组菜单、导出菜单、个人空间行菜单、删除 PDF 确认框是圆角 12；首页行菜单、「草稿卷更多信息」、「保存 PDF 到个人空间」对话框是圆角 8。作废口令对话框又是第三种（13px、无影子）。长得一样、干的事不同的也有：「草稿卷更多信息」菜单和「保存 PDF」对话框是同一种样子。
- **找题框在不同页样子不同**：首页 16px / 高 52，浏览页同一个输入框 13px / 高 34；首页出了结果后左内边距从 48 变成 84（前面多了东西），我的规则把它算成了另一种——这是同一个框的两个状态，算成两种是我方法的误差。外面的圆角、影子画在外框 `.concierge-intent-bar` 上，不在输入框本身。

## 五、证明

- **源码统计和页面实拍对一对**（`inventory.md` 第五节第 1 条）：页面上拍到的 67 个按钮写法位置在源码里全部找得到；源码 325 个按钮位置 = 324 个 `<button>` + 1 个 `<div role="button">`（`DraftPaperRail.tsx:274`，页面上归成「行」）。基线里的 324 只数 `<button>`，所以和 325 差 1。卡片类 10 处「只在页面」：源码里它们只是普通 `div`，靠 CSS 画出底色和影子，静态统计认不出，只有实拍认得出——这正是两种数都要的原因。
- **没拍到的**：九类源码写法位置的覆盖率在 5.7%（行）到 50%（底部提示、对话框）之间。没拍到的 477 个位置逐条写了原因（`data/uncaptured.json`），最大的一块是「需要生词或学生数据」（按钮 149、输入框 25 等），其次是「本地四组测试题跑不出这一块」和「出错时才出现」。
- **故意塞变体**（`seeds.mjs`）：在找题页按顶栏「生词本」按钮塞了三个——全新样子（品红、圆角 3px、11px）单独成一种，并被标出「圆角 3px 不在家族」「底色 #FF00AA 不在色阶」；差一点点的（圆角 +0.5px、字色红通道 +2）并进参照那一种并记为走样（「字色差 ΔE 0.7」「圆角差 0.5px」）；一模一样的复制是同一个精确签名、不算走样。三个都按预期找出来。塞的元素不计入任何数。
- **两轮重拍**（`data/determinism.json`）：在两个全新的本地网站上各拍一轮，候选 829 / 829、归类 527 / 527、每种样子和次数**完全一致**。
- **对比度、点击区域**用 WCAG 公式和 axe-core 4.14.0 的结果，不靠目测。

## 六、复核方的独立分组

复核方只拿到 `.scratch/component-inventory/reviewed/render.json`（那一刻的原始实拍数据：实算样式、位置、截图），没看我的分组和规则。对比只在这一份数据上做（`compare.mjs`，结果 `data/review-compare.json`）：

- **归哪一类**：813 条记录里一致 85.1%，Cohen κ = 0.776。主要分歧：顶栏头像 `topbar-avatar` 29 处我归「标签 / 小签」，对方归「不算」；草稿卷里每个题组外面的白底框 `draft-group-actions` 21 处，对方算「卡片」，我归「不算」（它和父元素同为白底，我的规则认为它没画东西）；另有 7 个我归「标签」的对方归「按钮」，13 个我归「提示条」的对方归「不算」、5 个归「空状态」。
- **样子**：按钮我分 43 种，对方 20 种。我的 43 种里 **37 种完整落在对方的某一种里**——差别主要是对方容差更宽（灰色每通道差 30 以内、高度差 10px 以内算一种），我按「差一点点」才并。跨了对方几种的 6 种，是我没把「只有图标」和「有字」分开、没把菜单项和普通文字按钮分开。
- **行**：我只分 1 种，对方按结构（列表行、篇章行、文件行）分 3 种。我的签名只看画出来的底、边、字，没看行内结构，这是我方法的缺口。
- **对话框**：对方 5 种，每种都完整落在我的某一种里，我分得粗。
- **干什么**：对方分得更细（按钮 43 件事对我 22 件）；对方分在同一件事里的，我也都分在同一件事里（成对精确率 1.0），所以对方是在我的分法上再细分，没有互相打架。例如对方把「去找题」「返回找题」合成「回找题页」，再和「打开个人空间」分开，我都归在「去别的页」。

复核方另外指出、我**用原始数据核实过**的问题：

1. 草稿卷空状态那句「请先添加题组，再下载 PDF 用于打印。」紧贴窗口左边缘（`draft-empty`，x = 0，宽 1440，无内边距），在主线上。
2. 首页加入一组之后，右下角「草稿卷（1 组）」按钮是禁用的（`home-added`，`App.tsx:1164`，`disabled={!currentDraftPaperId || …}`），原因没查（可能是加入后草稿卷编号还没回来）。
3. 听写页把共用顶栏改了样子（字重 400、返回按钮 16px 墨色），见上面第三节第 2 条。
4. 排版建议在「建议」状态下底色和页面底色相同、影子全透明（`draft-reorder-suggestion` `data-state=proposal`），采纳之后才变成卡片。
5. 首页「筛选」按钮的边框是暖灰 rgb(216, 216, 210)，其他按钮用冷灰。
6. 我第一版漏拍了撤销底部提示和三个菜单面板（菜单面板用 `FluidHoverList` 渲染，内部是动态标签，没被打上源码标记；底部提示是拍得太早）。**已修好重拍**，现在的数包括它们。
7. 两个场景（`reading-analysis`、`paper-intelligence`）的页面已在 2026-07-16 下线，打开只会回到首页。已从场景里去掉（`scenarios.mjs` 里写了原因）。

## 七、缺口和局限（照实写）

- **只有本地测试数据**：一套卷、四个题组、一个 owner 账号。生词、听写、学生相关的写法大多拍不到（需要生词或学生数据的位置 200 多个）；A3 拼版、出错、加载中的状态大多没走到。覆盖率见上。
- **整卷页拍不出**：`paper-browse` 四个场景在本地数据上都显示「没找到这份卷面」（`Cannot read properties of undefined (reading 'blocks')`），拍到的是出错页，不在主线上；没修，因为这一步不改网站代码。
- **没有线上数据、没有老师的使用情况**：「出现次数」是本地页面里的次数，不是老师真实点击的次数；主线是按「找题 → 加入 → 草稿卷 → 导出」的页面定的，不是按使用数据定的。
- **归类规则是我写的**：九类和「干什么」的规则、容差、P1 / P2 / P3 的切法，都只有我和清点脚本定过；复核方的结果说明了哪里分歧，但 Owner 没看过，同事访谈没做。所以全部标 **提案 · 单一来源**。
- **行内结构没进签名**（见第六节），行和卡片的种数偏少。
