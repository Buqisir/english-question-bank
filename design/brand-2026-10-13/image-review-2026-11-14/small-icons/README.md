**F 换成格子**（A、C 都带）：

- 改成两行台阶：缺口上面再挖一行，2 格宽，(15,21)(16,21) 雾白→绿。缺口顶到了鼻子下沿往下第 3 行，鼻子和缺口之间从隔 3 行变成隔 2 行（数格子）。

**改后的净空**（隔几格，0 = 贴着；三个文件一样，左右眼一样）：

### 观察（目测）

- **原尺寸**（`tryon-1x.png` 顶栏、`tryon-2x-tab.png` 标签）
  - A 的眼睛是两块方墨，分量快赶上鼻子，第一眼先看到眼睛。神情偏「瞪着」，往萌的方向偏了一点。
  - C 的眼睛是竖着的小墨条，看得清是眼睛，但鼻子还是第一视点。和现状比，C 只是「眼睛清楚了」，不是「眼睛变大了」。
  - C 的眼睛不是圆的。8 倍下看得出是竖长的；原尺寸下看不出竖长，只觉得眼睛深了一点。
- **F 脸斑**
  - 8 倍下，台阶缺口读成一个往上的尖，两瓣外下角圆了一点，和矢量 F 的方向对得上（`muzzle-study.png` 的 m2 对照最后一格矢量 F）。
  - 原尺寸下，A 和 A0、C 和 C0 几乎分不出来，只觉得鼻子下面的绿口子深了一点。台阶缺口在原尺寸下不比现状差，所以草稿保留了 F。A0、C0 留着作对照。
  - 削外下角（m3）在原尺寸下看不出来，只在 8 倍下有用。外下角削两层（m4）在 8 倍下脸斑显瘦，没采用。
- 矢量标志直接缩到 32×20（`muzzle-study.png` 最后两格）的时候，F 改前改后几乎没区别，眼睛只是两团灰墨。手排的格子比缩出来的清楚。

### 推荐（推荐，不是定案）：C

1. C 和大图眼睛只大 16% 的分寸对得上：C 每只眼 6 格，是现状的 1.5 倍；A 9 格，是现状的 2.25 倍（量）。A 在原尺寸下眼睛抢了鼻子，和「够成熟」（第 94 条）相反（目测）。
2. 改动少：C 每份文件改 8 格，A 改 14 格。两版的净空一样。
3. C 的代价是眼睛竖长不圆，8 倍下看得出来。Owner 如果觉得 C 在顶栏上还是不够「在」，再上 A。

## 二、16 格：修

坐标按 `app-icon-16` 写；`otter-head-16` 同坐标，mint `mark-16` 和 `mark-16-mono` 行号 +1。

| 文件 | 改了哪些格 |
|---|---|
| `app-icon-16`、`otter-head-16` | (4,7)(11,7) 雾白 `#F2FAF6` → 绿 `#72BFA4` |
| mint `mark-16` | (4,8)(11,8) 雾白 → 绿 |
| `mark-16-mono` | (4,8)(11,8) 透明 → 墨 `#191D18`（就是眼睛取证 README 里问题 ③ 的修法） |

改后：眼睛还是 1×2，到鼻 1，到外轮廓 1，都没变。

- **到脸斑还是 0。** 眼睛和脸斑不再共用一条边，但眼睛下角和 (3,7)、(5,7) 两格脸斑斜角相碰。照这套量法（切比雪夫距离），斜角相碰也算贴着。
  - 想真正隔开一格，得把 (3,7)、(5,7) 也改成绿，每边脸斑上沿就少掉 3 格。这超出了已定的「正下方那一格」，没有画。
  - 原尺寸下，眼睛已经从脸斑上沿分出来，读成一个点（目测）。
- **墨色版**：现状下眼洞和脸斑洞连成一个洞，量具分不出眼睛（量）。补墨以后，眼洞成了单独的洞（四连通），和脸斑洞也是斜角相碰。

### 16 格能不能带 F（`probe-16.png`）：带不了

- 16 格的缺口只有 2 格宽，在 (7–8, 10)。要做台阶，上一行就得比 2 格更窄，左右又要对称，做不出来。
- p2、p3 把缺口加高一行（(7,9)(8,9) 改绿）：绿口子直通到鼻子下沿，脸斑断成左右两块，左边一块从 34 格变成 16 格（量），鼻子像立在一根绿柱上（目测）。不能用。
- p1 两瓣外下角各削一格（(3,10)(12,10)）：8 倍下两瓣圆了一点，原尺寸下看不出来（目测）。不值得改。
- 结论：16 格只做已定的修法，不带 F。
