## 0. 说明

**范围.** DESIGN.md 和 PRODUCT.md 里讲品牌、外观、语气和界面规则的条款。每条查四件事：谁写的、什么时候写的、是 Owner 原话还是 agent 推广、现在还算不算数。最后一列写改写时它该去哪。

**版本.** 以 origin/main `707bb350`（2026-10-13 拉取）为准，行号和文件也按这一版。本地 main 落后 7 个提交，其中两个改了 DESIGN.md、PRODUCT.md 或图标理念页，见 §3。`design/icon-system-2026-09-15/motion-rules.md` 和 `docs/product/paper-pdf-products-v1.md` 只在 origin/main 上有。

**查法.** 用 `git blame` 和 `git log -S` 找每条第一次出现的提交，再对照三样东西：文中的 Owner 标注；图标套件 `design/icon-system-2026-09-15/brief.md` 和 `principles.md` 里记下的 Owner 原话；现网代码。提交作者大多显示为 Owner 的账号，看不出是谁写的，所以只能靠文中标注和评审记录判断。

**已定的两条规矩（Owner 2026-10-13）.**

1. **分工**：BRAND.md 管品牌，包括北极星、性格、语气、标志、颜色、水獭和插画。DESIGN.md 只留界面执行，包括 token、组件、间距、字号、动效和文案格式。PRODUCT.md 只留产品，包括为谁、做什么、主线和边界。
2. **效力门槛**：和 Owner 原话对得上，或经过真实页面验收，才算「已定」。Agent 的概括和推广一律降为「提案」。`docs/agents/case-law.md` 第 3 行的元规则是同一个意思：新的硬规定要有真实事故或 Owner 拍板背书。

**Owner 审表后的四个决定（2026-10-13）.**

1. **Paper Mono**：三种用法放进真实页面并排对比，看过再定（BRAND.md §3.3，Paper 文件 L 画板）。2026-10-13 看完，按建议定：整个界面不换，只换数字不单独做，字标留到定名字时再比（BRAND.md §3.3、决策 18）。
2. **「提案（沿用中）」整批确认为已定。** 下面表格里凡是写「提案（沿用中）」的部分，一律读作「已定」。例外：P09 括注里的「可爱 =」由 D10 管，仍是提案。
3. **题型六色删除**（D03）。
4. **三份文件现在就改写**；没有逐条提到的条目，按最后一列执行。

**「依据」一栏用六个词.**

| 词 | 意思 |
| --- | --- |
| 原话 | 仓库里记有 Owner 的原话，并注明出处 |
| 拍板 | 文中写明 Owner 拍板、确认或要求，带日期，但没有逐字原话 |
| 验收 | Owner 在真实页面上确认过效果 |
| 推广 | Agent 把 Owner 的局部意见推到别处，或替它起了名字 |
| 引入 | Agent 从外部资料搬来，比如 Geist、调研文章、impeccable 设计技能 |
| 存量 | 早期基线（2026-06-03 起）或老方向留下来的，没有单独的决定记录 |

**「效力」一栏用五个词.**

| 词 | 意思 |
| --- | --- |
| 已定 | 过了门槛，照此执行 |
| 提案 | 没过门槛，等 Owner 确认 |
| 提案（沿用中） | 现网在用，但没有原话或验收记录。代码不动，只是不再当铁律。Owner 可以整批确认 |
| 作废 | Owner 明确推翻过 |
| 过期 | 写的内容和现在的代码或 Owner 的新决定对不上 |
