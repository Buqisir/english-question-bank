- **图片地址**：`src/` 里的 Paper 网址都换成了相对 `src/` 的仓库路径（对照表在 `source-0.5/README.md`）。同一张图仓库里有两处时用 `design/` 下那份，不用 `app/public/` 下的。

## 怎么重新生成

脚本只用仓库里已装的东西：`app/` 的 vite（自带 oxc 转 JSX）、react、react-dom/server、Playwright，`server/` 的 pdf-lib。仓库里没有加新依赖。

1. 后备字体装到仓库外的临时目录（两个 npm 公共包，只在生成时读，不进仓库）：

   ```bash
   TMP=$(mktemp -d)
   npm install --prefix "$TMP" --ignore-scripts --no-save \
     @fontsource-variable/noto-sans-sc@5.3.1 @fontsource-variable/noto-serif-sc@5.3.1
   ```

2. 生成（在仓库根目录）：

   ```bash
   MANUAL_FONTSOURCE_DIR="$TMP/node_modules" node scripts/brand/build-manual.mjs --compare
   ```

   - 默认输出：`视觉规范手册-草案0.6-预览.pdf`、`build/png/*.png`（每次先清空旧 PNG）、`build/build-report.json`。
   - `--compare` 会把每页和 `source-0.5/png/` 里的 Paper 截图比一遍，结果写进 report。`--diff-dir <临时目录>` 可以另存差异图。
   - 其他选项：`--out`、`--title`、`--png-dir`、`--report`、`--keep-html <临时目录>`、`--only 04,16`（只出这几页的 PNG 和检查，不出 PDF）。详见脚本开头的注释。
   - Chromium 默认用 `/opt/pw-browsers/chromium`（存在时），或者用 Playwright 自己找到的那个；也可以用环境变量 `MANUAL_CHROMIUM` 指定。
   - 跑完会打印每页的图片数、差异比例和检查问题，最后一行是「页面报错 N 条」。

3. **在 Mac 上出正式版**：在装了苹方的 Mac 上跑同一条命令，把输出名里的「预览」去掉：

   ```bash
   MANUAL_FONTSOURCE_DIR="$TMP/node_modules" node scripts/brand/build-manual.mjs \
     --out "design/brand-2026-10-13/manual/视觉规范手册-草案0.6.pdf" --title "视觉规范手册 · 草案 0.6"
   ```

   脚本会自己检查苹方在不在。苹方在的时候字体栈里苹方排在前面，后备字体不起作用。

### 字体：为什么这台机器只能出预览版

- `src/` 里的字体栈原样保留，苹方在前（`"PingFangSC-Regular", "PingFang SC", system-ui, sans-serif`；标题用 `"Noto Serif SC"`）。
- 生成时只改出来的 HTML，不改源文件：在每个字体栈的 `system-ui` 前面插入 `Noto Sans SC Variable`，在 `"Noto Serif SC"` 后面插入 `Noto Serif SC Variable`。
- 这台机器（Linux 容器）没有苹方，也没有装 Noto Serif SC，所以正文用的是 Noto Sans SC，标题用的是 Noto Serif SC（fontsource 版）。Noto Sans SC 和苹方是两套字形，**字宽和字形都和 Mac 上不同**：同一段文字在这里通常更宽，换行位置会变。所以这里出的叫「预览版」，在装了苹方的 Mac 上重跑同一条命令才是正式版。
- Paper Mono 和 EQB Termes 这台机器上没有，08、16、22 页的等宽字和 Times 字样由系统字体代显（目测）。
