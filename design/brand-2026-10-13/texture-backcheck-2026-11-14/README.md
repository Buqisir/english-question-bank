## 一、现状（只量，不判断）

### 1.1 量法

- **矢量**：在浏览器里摆上 SVG，用 `getPointAtLength` 沿轮廓取点、`isPointInFill` 判里外，裁切路径也算进去，全在各文件自己的 viewBox 坐标里。
  - 眼睛：大小相近、左右排开的一对墨形里最大的一对。眼径取外框宽高的平均。
  - 鼻子：两眼中点下方、宽在 0.25–1.2 个眼距之间、离中点最近的墨形。
  - 须点：比眼睛小的其余墨形。
  - 净空：两个形的轮廓之间最近的距离。
  - 头宽：从两眼中点沿两眼连线往两边走，走出头（雾薄荷）、脸斑和五官为止。耳朵在眼睛上方，不在这条线上，所以「头宽」不含耳朵。
  - 头高：沿垂线往上走出轮廓，往下走到围兜色或轮廓边。
  - 面积：网格取样（头区 260×260 点，眼睛各 60×60 点）。
- **逐格画版**：按颜色分块。眼睛是最上面两块墨，单色版里是最上面两个封闭的透明洞。
  - 净空 = 两块之间的切比雪夫距离减 1，也就是中间隔几格；0 表示贴着，包括斜角贴着。
  - 外轮廓 = 透明格加上和画布边连着的雾白底板格。
- **截图**：一只眼睛实际占几个物理像素，用两种数表示。
  - 理论眼径 × 设备像素比。
  - 截图里眼睛附近每个像素按线性光强度算墨的覆盖率。「等效满墨像素」是覆盖率加起来，「≥50% 的像素」是数格子。

## 二、眼睛对比稿（母版没动）

### 2.1 怎么做的

- 五档：1.00（现状）、1.10、1.20、1.30、1.45，眼睛的 `rx`、`ry` 乘这个数。
- **处理 A 位置不动**：圆心不动。
- **处理 B 保持净空**：放大后，眼到鼻、眼到脸斑边的最近距离都不小于现状。在母版坐标里网格搜索（步长 0.25）最小的「往外 + 往上」移动，三套用同一组移动量。头像和标志是母版单位；App 图标里乘 0.0984。

### 2.4 每档的观察（目测）

看的是 `sheet-*`、`check-*`、`shots/try-*`。

- **1.00 现状**
  - 160px：眼睛是两颗小黑点，鼻子是脸上最先看到的东西，神情安静、偏成年（目测）。
  - 32px 以下：眼睛开始被鼻子和脸斑的边吃掉。
    - 头像 16px 1x 只有 0.95 像素，模糊 1px 后眼心对比 0.03，等于没了（量）。
    - 标志 20px（顶栏 2x 的大小）模糊后 0.26。
    - 登录页左上角 1x 实拍只剩约 2 个满墨像素，须点成了灰斑（目测）。
  - Owner 说「眼睛有点小」，在小尺寸上有数据支持；在 160px 上看不出小（目测）。
- **1.10**
  - 大尺寸上和现状几乎分不出（目测）。
  - 标志 20px 模糊后从 0.26 到 0.37 / 0.42。
  - A 的眼到脸斑净空从 12.5 降到 9.7（−22%），B 只要外移 2、上移 2.75，看不出位置变化（目测）。
- **1.20**
  - 32、64px 上眼睛明显更「在」，标志 20px 模糊后 0.41 / 0.51，标志 16px 0.30 左右，大约是现状的两倍（量）。
  - 160px 上仍是小黑点，神情没变（目测）。
  - A 到脸斑剩 6.8，开始显得眼睛「坐」在脸斑上沿（目测）；B 上移 5.25 以后没有这个问题。
- **1.30**
  - 160px 上眼睛成了脸上第一眼看到的东西，和鼻子抢（目测）。
  - A 到脸斑只剩 4.0（原来的 32%），贴着脸斑像长在脸颊上，脸显得更圆更小（目测）。
  - B 上移 7.75 以后眼睛离头顶近了，额头变短，头显得更大（目测）。
  - 小尺寸上比 1.20 的增益不大（标志 20px 模糊后 0.50 / 0.59）。
- **1.45**
  - 160px 上眼睛大而圆，读起来是「萌」（目测）。
  - 眼径 ÷ 眼心距 0.237，眼睛占眼距近四分之一（量）。
  - A 的左眼压进脸斑 0.2（量），左右不对称地贴边。
  - B 上移 11.75，额头明显变短（目测）。
  - 小尺寸最清楚：标志 16px 模糊后 0.38 / 0.50。

### 2.5 从哪一档开始滑向「Q 版、超大眼睛、幼稚」

- **大尺寸（64px 以上）从 1.30 开始滑，1.45 越过去了（目测）。** 理由有三条。
  - 1.30 起眼睛压过鼻子成了第一视点。BRAND §1.7 的反面是「超大眼睛」；我们的角色靠宽墨鼻和 ∴ 须点认出来，眼睛一抢，读法就从「海獭」变成「大眼小动物」（目测）。
  - 1.30-A、1.45-A 眼睛贴到脸斑上沿；B 要上移才保得住净空，额头就变短。「头大、额低、眼大」正是 Q 版的三件事（目测）。
  - 量上：1.45 的眼径 ÷ 头宽 0.106，是现状 0.073 的 1.45 倍；眼睛面积从头区的 1.1% 到 2.4%，翻了一倍多。
- **小尺寸（32px 以下）一直到 1.45 都没有 Q 版的感觉（目测）**：那时眼睛只有 1–3 个像素，看到的是「有没有眼睛」，不是「眼睛大不大」。

### 2.6 推荐（推荐，不是已定）

- **小图标（32 CSS px 以下：浏览器标签、顶栏、登录页左上角、行内小头像）**：眼睛可以加大。
  - 矢量小尺寸版推荐 **1.20-B**（外移 3.75、上移 5.25）。它在标志 16 / 20px 上把模糊后的眼睛深度提到现状的约 2 倍，净空和现状一样，大尺寸也不显 Q。做法是另出一张「小尺寸用」的标志 SVG，只在 ≤32px 时用；不改大母版。
  - 32 格推荐备选 **a（3×3 外扩上延）**，或更克制的 **c（2×3 上延）**。b 净空最大，但眼睛上移后额头短了一格（目测）。
  - 16 格推荐**先不改，或用 b（1×3 上延）**。a 的 2×2 就是以前试过、被判「太重」的那一版；c 顶到外轮廓。16 格真正卡住的是眼下贴着脸斑，要解决得动脸斑格（问题 4）。
- **大角色（64px 以上：状态图、宣传、3D）**：**保持 1.00**；Owner 若仍嫌小，最多 **1.10-B**。
  - 大尺寸上眼睛不小（目测）；1.30 起滑向 Q 版。
  - 这和「小尺寸加大、大尺寸克制」的通常做法一致。
- **先修净空，再谈加大**：P、state-01、state-02 的眼到脸斑只有 0.6–2.3 单位（不到眼径的 8%）。头像母版是 0.22 个眼径，这几张远比母版贴边（见第三部分）。
