# ADR 0005: C7 Versioned Paper Asset File Protocol

Status: Accepted for C7 planning.

## Context

C7 needs repeatable paper import, republish, QA, and future cloud
migration. The current app serves paper assets as static files. The
protocol must keep latest teacher routes simple while preserving
versioned snapshots for review and rollback.

## Decision

Each paper asset lives under:

```text
app/public/paper-assets/<paperId>/
```

Versioned files live under:

```text
app/public/paper-assets/<paperId>/versions/vN/
  raw/
  paper-asset.json
  answer-key.json
  import-meta.json
  analyses/reading-choice-analysis-v1.json
  validation-report.json
  publish-report.json
```

Teacher-facing latest files live under:

```text
app/public/paper-assets/<paperId>/latest/
  paper-asset.json
  answer-key.json
  import-meta.json
  analyses/reading-choice-analysis-v1.json
```

`latest/` is not a filesystem symlink. It is a real directory so Vite
static serving and future cross-platform development stay simple.

Publish writes a temporary latest directory and renames it into place
after DB commit.

Version numbers are system-generated by max existing version + 1.

## Versioned Routes

Teacher routes default to latest.

Optional version-pinned QA routes may use `version=vN` to read
`versions/vN/`.

## Consequences

- The normal teacher URL does not need a version parameter.
- QA can verify both latest and version-pinned views.
- Future cloud migration can map `versions/vN/` to object-storage
  prefixes and `latest/` to the current object set.

## Open Implementation Detail

Whether `versions/` should be committed to git or ignored is a DEV /
repo-storage policy decision. C7 must avoid accidental large fixture
churn either way.
