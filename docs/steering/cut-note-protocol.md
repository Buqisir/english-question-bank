# Optional cut note

A cut note preserves a material lesson; it is not a merge gate.

Write `docs/cuts/<feature>/cut-note.md` when a release:

- changed a recurring product rule;
- exposed a repeated failure pattern;
- settled a visual or teaching decision future work must know;
- left a meaningful follow-up risk;
- taught a useful process lesson.

Skip it for routine tickets and small fixes.

```text
Feature:
Status:
PR / branch:

Completed:
- ...

Wrong assumptions / bugs:
- ...

Good decisions:
- ...

Watch / next:
- ...
```

Keep it short and honest. Distinguish static verification from browser/owner
QA. Do not turn the note into another completion report or lifecycle record.
