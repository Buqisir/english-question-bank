# 经典模式退役方案（提案 v1，待 owner 圈判断题）

前置：`inventory.md`（盘点+证据）。roadmap 决策 6 精神：一体化 ≠ 全塞进
找题页——60 分 = 一个界面 + 一个不碍眼的管理角落。

## 方案骨架（PM 推荐）

拆三刀，每刀独立可用、可验：

### 刀 1「管理角落」

- topbar 的 4 个策展按钮（导入资料/整卷导入/AI 导题/打标签）+ 闭环面板
  收敛成 owner-only 的**一个「管理」入口**，点开进独立全屏管理台
  （`?view=admin`，样式复用现有工作台骨架）。
- 管理台内分区：导入（资料/整卷/AI 导题三入口）+ 数据维护（闭环体检
  面板搬家 + 打标签 backfill）。
- 模式切换按钮退役；`homeMode` 状态机本刀先留（classic 分支变死代码，
  刀 3 清）。
- 顺手收掉 ui-blemish-list №1（topbar 按钮墙）。

### 刀 2「题组详情进 AI 模式」

- 题组详情从 classic `viewMode='detail'`（~1300 行）抽成独立视图，
  ConciergeDesk 题组卡片加「详情」入口。
- member 只读（原文+解析展示），owner 额外见编辑/解析生成/标签/难度
  按钮（复用 isOwnerView，服务端闸已在）。
- 这刀对 member 是纯增益：解析是产品核心价值，现在 member 根本看不到。

### 刀 3「尸体清理」

- `homeMode`/`viewMode` 状态机删除；经典列表、经典侧栏、排版预览、
  题库管家聊天面板删除；死 CSS 顺手清（老挂账）。
- 「新建题组」死路径确认后清。

## 判断题（owner 圈答案，带 PM 推荐）

**Q1 管理角落形态**
- A（推荐）：topbar 一个「管理」按钮 → 独立全屏管理台，分区收纳
- B：不建新页，4 个按钮维持 topbar 现状，只把闭环面板搬成弹窗
- C：其他（说想法）

**Q2 题组详情给不给 member 看**
- A（推荐）：只读详情对 member 开放（原文+各题型解析），编辑/生成
  按钮 owner-only——解析是给同事的核心价值
- B：详情整体 owner-only，member 只看卡片摘要（现状延续）

**Q3 paper-sets（题集）的命运**——事实：AI 模式零消费，纯策展侧闭环产物
- A（推荐）：闭环面板的「生成/更新整卷题集」随体检搬管理台；经典侧栏
  「保存题集/载入」和排版预览退役（草稿卷工作台已对等覆盖组卷+导出）
- B：「保存题集/载入/排版预览」也搬管理台（如果你的真实工作流还在用）

**Q4 开放题**：经典模式里还有没有你日常离不开、上面没列到的操作？
（有的话说一句，我去盘它的新家。）

## 规模与风险

- 刀 1 medium（新路由页+搬 workflow 面板 JSX，无数据契约变化）。
- 刀 2 medium-large（1300 行 JSX 抽取 + member 可见面变化 = 产品边界，
  按流程加 PA）。
- 刀 3 small-medium（纯删除，verify 回归兜底）。
- 服务端零改动：41 条 ownerOnly 闸原样，管理台走同一批 API。
- 全程 member 视角零变化（除刀 2 的详情增益），M0-3 的
  verify-owner-gate/verify-auth-gate 全程回归。
