# 04 — Shared rich whole-paper and active-consumer compatibility

Status: blocked
Blocked by: 03 — Shared source-faithful ordered composition

## What to build

Close the remaining shared rich-content and active-consumer gaps before either
real parity paper migrates. Extend the generic trusted transcription/compiler
route for a real table nested inside `framed_columns`, exact Application and
Continuation source composition, and a source-backed Passage Figure caption.
Preserve current active consumer behavior through the Canonical Consumer
Interface or, only where that interface cannot yet project an accepted field,
one bounded read-only compatibility Adapter.

This ticket owns B04, B05, B06, and B10 from the
[real parity frontier](../research/real-parity-frontier-2026-08-26.md). It does
not contain Shenzhen, `paper-2026-i`, or Jining data and does not retire any
paper-specific path.

## Allowed and forbidden scope

- Allowed: generic validated rich-content transcription shapes, trusted
  adapter/compiler projection, Canonical Consumer Interface coverage, and at
  most one thin read-only compatibility Adapter for current active consumers.
- Active-consumer compatibility means Screen, Student Print, Teacher Print,
  PDF, Analysis, and current question listing, detail, search, similar-question,
  and figure behaviors remain semantically available from the published
  Canonical Paper and its approved sidecars.
- Unaffected historical assets remain supported under their immutable
  authority.
- Forbidden: exact byte/path recreation of standalone answer-key, import-meta,
  or Listening three-file public outputs; a legacy figures manifest for media
  already canonicalized; renderer/CSS or authority changes; a write-capable
  compatibility route; paperId branches; per-paper data or retirement;
  production mutation; or unrelated historical migration.

## Acceptance criteria

- [ ] `framed_columns` can contain the accepted renderer-neutral real-table structure in exact declared source order, with complete row/cell ownership and fail-closed reference validation rather than a page screenshot or caller-authored Canonical subtree.
- [ ] Application Writing preserves the exact source composition, including provided title/skeleton, prompt/notice references, and declared ordering, without adding adapter-authored visible evidence prose.
- [ ] Continuation Writing preserves all source paragraph boundaries and current contract-shaped material instead of collapsing them into one paragraph or downgrading an accepted modern shape to `legacy_opaque`.
- [ ] A Passage Figure may retain an exact non-empty source caption with stable figure ownership, source bindings, and normal shared consumption; omission or mutation fails closed when the source declares a caption.
- [ ] Screen, Student Print, Teacher Print, PDF, Analysis, and question listing/detail/search/similar/figure behaviors obtain semantically equivalent data through the Canonical Consumer Interface or the single bounded read-only Adapter, with Student/Teacher answer separation intact.
- [ ] The compatibility route neither reconstructs legacy public-extra bytes/paths nor breaks unaffected historical assets; migrated papers have one supported generic publication route after their later parity tickets retire the old inputs.
- [ ] No consumer reconstructs paper meaning, no renderer or authority changes, and no paper identity selects rich-content or compatibility behavior.
- [ ] Focused public Format 2 Job, rich Canonical compilation, active consumer/interface, historical-asset compatibility, schema/syntax, and `git diff --check` checks pass. Real-paper data, retirement, full-suite closure, and final independent review remain downstream.
