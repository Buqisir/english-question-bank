## 一句话方向

草稿卷「屏幕预览」与「导出 PDF」的分页 parity，靠**服务器当唯一排版真源**实现：
服务器把卷子排一次分页，产出（a）**分页好的活页面**给前端预览、（b）PDF，**同源**。
前端显示活页面并在每道题上叠操作按钮（复用刀A 贴纸条 + rail，与 rail 目录**同一套操作**）。
→ 屏幕看到的与导出的由同一次服务器分页产生：所见即所印、所有老师一致。

## 决策链（怎么走到这一步）

1. **问题**：屏幕预览（自研 JS 贪心）、浏览器打印、PDF（Vivliostyle）三套分页各算各的，
   C8 立项搁置至今。见 `tech-recon.md`。
2. **波及/保真调研**：Vivliostyle 只在两处 PDF 导出（草稿卷=活、旧系统=孤儿路由），是**偏离
   C8 原设计**（原设计=浏览器 print-to-PDF，`decisions.md:162-164`）、底层就是 Chromium；
   解析面板是纯 React 屏幕组件、不碰它。保真顾虑消解（试卷要的 break-inside/页码浏览器原生都有；
   orphans/widows 项目从没用过；动态页眉试卷不需要）。见 `project-feasibility.md`、
   `research-pagination-engines.md`。
3. **方向演进**：A1（喂断点/打补丁→弃）→ A2（纠回原设计/浏览器出片）↔ paged.js（换强轮子）。
   owner 定调「协调主功能、不怕重、要强轮子别打补丁」。
4. **owner 服务器担心 → 铁律**：分页必须**服务器算一次当唯一真源**，老师电脑只显示，
   消除「每个老师电脑不一样」。这条把天平推向「服务器出片」。
5. **spike 验证**（`scratchpad/spike-headless-pagination.mjs`，见下）。
6. **owner 追问「卷子上叠按钮」** → 预览不能是死图（死图定位不了每题位置叠按钮），得是
   **活分页页面** → paged.js 的另一本事（产出真实分页活 DOM）在此派上用场，待 PA 定夺。

## spike 证据（headless Chromium 出片可行性）

- **出 PDF**：可行；**确定**（同卷跑 3 次分页字节一致、都 9 页）；**延迟 OK**（复用 chromium
  实例每次 ~110–125ms，冷启动 chromium 额外 60–300ms）。
- **长阅读自动按段落跨页**：确认（pdftotext 实证，VPP passage 第 4 页拆到第 5 页、段落中间断）
  → **换浏览器引擎，长阅读病根白给解决**。
- **朴素「getBoundingClientRect + 页高」提取分页 = 证伪**：`break-inside:avoid` 把整题推下页
  留白，未分页 DOM 看不到这段留白 → 提取算 7 页 / 实际 PDF 9 页，越往后差越大。
  **⇒ 不能靠「服务器报清单、前端重绘」；要真实分页 DOM（paged.js / column-width fragmentation）
  才能拿准每题位置**——这也正是「活页面 + 叠按钮」需要的能力。

## 拍定方案（路甲升级版：活分页页面）

- **服务器唯一真源**：服务器排一次分页，出「分页活页面（预览用）+ PDF」同源。
- **预览 = 活页面**（非死图）：前端显示它，在每题叠操作按钮（上移/下移/前置分页/移除），
  与 rail 目录同一套操作逻辑。刀A 的 rail + 贴纸操作条基本复用。
- 纯「拖到任意位置」的连续拖拽在活页面上弱化，靠按钮 / rail 拖拽通道补。
- **出片引擎**：草稿卷 PDF 从 Vivliostyle 改为与预览同一分页真源出（浏览器原生 / paged.js，PA 定）；
  旧系统 Vivliostyle 孤儿路由不动。
- 自研 `paginateA4Preview` 作为预览真源**退役**。
- **走路甲后自动消解**：长阅读拆段落（引擎白给）、画布对齐（只剩一个画布）、提取分页
  （不重绘、直接显示活页面）。

## 拆刀

- **本刀（刀B，parity 地基）**：服务器出「分页活页面 + PDF」同源、前端预览显示活页面 + 叠按钮
  （复用刀A rail/贴纸）、退役自研分页、Vivliostyle 草稿卷这条换掉。做完「预览==打印」解决、能用、能上线。
- **挪出、排后面单独做**：A4/A3 打印形态 + 同面判据（原 program 刀B 扩容）；分页建议引擎改真分页
  衍生（路甲下服务器有真分页，自然可做）。

## PA 要钉死的核心问题

1. **技术方案**：服务器怎么产出「分页好的活页面 + 每题精确位置」？paged.js（服务器跑 / 前端跑）
   vs column-width fragmentation 模拟 vs 其他——可行性 + 推荐 + 风险（paged.js 稳定性 / 大文档 /
   `@media print` 样式泄漏是否因预览容器形态而规避）。
2. **活页面 ↔ PDF 一致性**怎么保证/验证（同一次渲染出两者，还是两次？两次则确定性/字体如何锁）。
3. **预览架构**：前端显示活页面 + 叠按钮 + 复用刀A rail/贴纸/scrollspy 的交互回归边界。
4. **服务器渲染性能/并发**：每次编辑重排的延迟、chromium 实例池。
5. **契约边界**：动 `print-renderer` / `draftPaperStore` / 退役 `paginateA4Preview` / Vivliostyle
   退役范围；schema 动不动（本刀不含 A4/A3 字段 → 大概率不动 schema）。
6. **拆刀 Forbidden**：A4/A3、分页建议引擎明确划出本刀。
