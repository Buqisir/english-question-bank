# Ticket 20 backend canonical import pilot QA checklist

Use this checklist only from the exact implementation HEAD after its required
independent Standards + Spec review passes. Do not reuse artifacts from an
earlier commit and do not provision QA from the implementation task.

## Provision

From the saved worktree, run:

```sh
node scripts/verify-paper-canonical-import-pilot.mjs \
  --actual-artifacts \
  --qa-server
```

The command replays the checked-in local source package through zero-write dry
run, atomic publish, exact reload, restart/retry, rollback, and supported
rendered consumption. It writes `HEAD.txt`, `evidence.json`, PaperSurface
plain/lecture HTML + PNG, Student/Teacher Print HTML, and direct Chromium
Student/Teacher PDF under:

```text
.scratch/paper-canonical-ticket-20-qa/<HEAD>/
```

The process prints exact HTTP URLs for `plain` and `lecture` Screen,
Student/Teacher Print HTML, and Student/Teacher direct Chromium PDF. The four
artifact routes serve only the generated bytes from the exact
`.scratch/paper-canonical-ticket-20-qa/<HEAD>/` directory, declare HTML/PDF
content types, and return 404 for unknown or traversal paths. Before reporting
ready, the command itself reloads all four artifact URLs, checks their bytes
against the generated files and their content types, and proves that the
localhost server remains alive.

The process keeps the exact temporary SQLite, API, Vite server, paper-assets
root, and HEAD-scoped artifact server alive until it receives SIGINT/SIGTERM.
The QA-provisioning task must verify `HEAD.txt` equals the independently
reviewed HEAD, open all six printed HTTP URLs, and smoke-check that each loads
before returning the canonical owner-QA handoff. Do not substitute local file
paths for the four printed artifact URLs. Stop the process only after owner
QA; its temporary runtime root is then removed, while the HEAD-bound artifact
directory remains.

## Owner checks

1. Reading passages render exactly one centered `A`, `B`, `C`, and `D` at
   their respective passage starts in plain/lecture Screen and Student/Teacher
   Print/PDF. The digest-bound crops are normalized only by their local Latin
   baseline step: heading-to-letter is `1×`, prior-content-to-letter is `2×`,
   and letter-to-first-passage-line is `1×`. Screen maps those ratios to its
   actual 24px line step, so A is 24±1.25px after its tagged heading and B–D
   are 48±1.25px after their exact tagged predecessor Groups. Print/PDF keeps
   a per-group tagged Reading heading and maps `1×` to 18±1pt; its
   letter-to-first-line step remains 18±0.5pt. No JPEG pixel is treated as a
   CSS pixel or converted to points. The letter has no extra web margin,
   matching the method, formulas, crop samples, and tolerances in
   `20-reading-passage-letter-reference-measurements.json`; Seven Choices,
   Cloze, Grammar Fill, Writing, and inactive Listening show no passage letter.
2. Plain PaperSurface shows the complete paper once in source order and no
   answer/lecture row; lecture PaperSurface keeps the same paper structure and
   exposes the selected official answer and teaching panel.
3. Student Print HTML and Student Chromium PDF contain no answers or
   explanations. Teacher Print HTML and Teacher Chromium PDF add answers
   without changing section order, question identity, wording, writing
   response regions, or canonical layout identity.
4. Screen and Print/PDF preserve Reading, Seven Choices, Cloze, Grammar Fill,
   Application Writing, and Continuation Writing semantics; Listening remains
   inactive and has zero current-surface occurrence.
5. `evidence.json` records dry-run zero mutation, v1 publish, idempotent v2
   recovery retry, rollback to the exact v1 digest, only the `screen` and
   `print_pdf` consumers, the accepted reference-measurement digest, and
   Screen/PDF A–D exact predecessor bindings, ratio-mapped baseline geometry,
   letter boxes, and following-line geometry within the recorded tolerances.
6. The QA directory and immutable import version contain no generated `.docx`,
   OOXML/XML, or DOCX-converted PDF. The source PDF is preserved byte-identical
   inside the local immutable version and direct PDF output never invokes
   LibreOffice/soffice.
