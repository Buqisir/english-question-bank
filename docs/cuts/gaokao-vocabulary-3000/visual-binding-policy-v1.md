# 高中课标 3000 词视觉绑定策略 v1

- **状态**：Owner 决策已锁定；全量内容生产必须遵守
- **适用范围**：高中课标 3000 词的选图、视觉 manifest、提示卡及使用视觉的练习界面
- **资产范围**：当前只使用逐张选择的 Koboyo 原始 SVG；不授权批量镜像、改编图或独立原创图进入正式资产
- **关联规范**：[`spec.md`](./spec.md)

## 1. 决策

每个 Vocabulary Entry 仍然只有一个独立视觉绑定，但“视觉绑定”不再等同于
“一张图脱离文字也必须让人猜出这个英文单词”。视觉分为两种模式：

| 模式 | 适用情况 | 成立条件 |
| --- | --- | --- |
| `direct-sense` | 具体名词、动作、人物、地点，或已有公认视觉隐喻的概念 | 图本身直接对应冻结的首要教学义，可在只显示单词的界面单独出现 |
| `sentence-scene` | 连词、介词、副词、关系词、多义词及其他难以单图表达的抽象词 | 图准确描绘一条已批准例句的具体场景，并且只与该条原句及目标词高亮共同出现 |

选择顺序固定为：

1. 先寻找准确的 `direct-sense` 原图。
2. 没有直接匹配时，把一条已批准例句转成具体场景，寻找准确的
   `sentence-scene` 原图。
3. 两种模式都没有合格原图时，标记为视觉缺口并提交 Owner 决策；不得为了填满
   manifest 使用牵强图、拼图、改编图或未批准的原创图。

这不是降低语义标准。`direct-sense` 的语义单位是“词的教学义”；
`sentence-scene` 的语义单位是“图 + 与它绑定的原句 + 目标词高亮”。两种模式有
不同的 QA 对象，不能拿“脱离句子能不能猜词”否决本来就表达关系的句义图。

## 2. 为什么大图库仍会出现“找不到图”

问题主要不在数量，而在检索单位错位：图库索引的是人、物、动作和场景；
`however`、`unless`、`despite`、`throughout` 等词表达的是两个命题之间的转折、
条件、让步或时间范围。直接搜索抽象词，容易得到随意的箭头、问号或人物表情，
它们与目标教学义只有联想关系。

改进后的检索单位是：

`冻结教学义 → 已批准例句 → 主体 + 动作 + 对象 + 地点/条件/时间`

例如，不搜索 `otherwise` 本身，而从 “Hurry up, otherwise you'll miss the
bus.” 提取“公交车正在离站，一个人在追车”这一可见场景。图负责让句子变得可见，
句子负责让目标词在关系中成立。

## 3. 例句绑定合同

### 3.1 唯一锚点

- `sentence-scene` 必须绑定一个稳定的 `visualSentenceId` 和原句文本哈希，指向某条
  已批准例句的完整原文；图片、句子和目标词高亮共同构成一个不可拆散的教学单元。
  原句文字变化会使绑定失效，必须重新选图或重新 QA，不能只保留旧 ID。
- 当前提示卡固定显示候选 A，因此用于提示卡的 `sentence-scene` 原则上绑定候选
  A。若 B 或 C 的场景明显更合适，应在冻结 Set 之前调整候选顺序，把该原句完整
  提升为 A；不得为迁就某张图而改写句子或改变教学义。
- 冻结后不得通过重排 A/B/C 使既有 Set 漂移。若冻结后才发现只有 B 或 C 有合格
  场景，该图只能出现在显示同一原句的界面；提示卡不显示它，并把 A 的视觉缺口
  留给重新选图或 Owner 决策。

### 3.2 界面显示

- `direct-sense` 可以在只显示单词的判断正面或其他无例句界面单独出现。
- `sentence-scene` 不得在只显示单词的判断正面单独出现；显示图片时必须在同一可见
  单元中显示其完整绑定例句，并高亮目标词。
- 如果练习当前使用候选 B/C，而图片绑定的是 A，必须隐藏该图；不得拿 A 的场景去
  解释 B/C。未来若要在 B/C 上配图，应分别建立句级视觉绑定，不得复用一个不对应
  的场景。
- SVG 内不得写入目标英文词或答案。界面负责句子与高亮，资产本身保持无文字，
  避免在判断和练习中泄题。

## 4. 逐词检索流程

1. **冻结教学义**：明确这张图服务的首要核心义，不试图把一词多义全部塞进一张图。
2. **尝试直接图**：用具体人、物、动作或公认隐喻检索 Koboyo；候选必须原样使用。
3. **选择视觉例句**：没有直接图时，从三条已批准例句中选择最具体、最少背景知识、
   最不容易引入歧义的一条。
4. **拆成场景查询**：记录主体、动作、对象和必要的地点、条件或时间；不用抽象词本身
   作为唯一查询词。
5. **逐张核验原图**：候选图必须准确覆盖句中可见事实，不得添加与原句矛盾的人数、
   方向、时间、地点或物体状态。
6. **保存 receipt**：记录官方页面、SVG 地址、授权页、检查时间、原始哈希和中文 alt。
7. **按模式 QA**：直接图看“图 ↔ 教学义”；句义图看“图 + 原句 + 高亮 ↔ 教学义”。

若一条批准句没有合适场景，可依次检查另外两条批准句。不得先挑中一张漂亮图，再
倒推或改写例句来配合它。

## 5. 建议的数据合同

每个 Entry 的视觉记录至少包含：

```json
{
  "visualMode": "sentence-scene",
  "teachingSenseId": "unless-condition",
  "visualSentenceId": "candidate-a",
  "visualSentenceTextSha256": "...",
  "sceneQuery": {
    "subject": "person",
    "action": "trying to enter",
    "object": "locked gate and key",
    "condition": "entry requires the key"
  },
  "bindingRationale": "图呈现例句中的进门条件，目标词在图句组合中表达除非",
  "asset": {
    "sourcePageUrl": "https://koboyo.com/icons/...",
    "sourceSvgUrl": "https://koboyo.com/...svg",
    "licenseUrl": "https://koboyo.com/icons/license",
    "checkedAt": "2026-08-11",
    "sha256": "...",
    "version": "koboyo-original-v1",
    "alt": "一人拿着钥匙站在锁着的门前"
  }
}
```

`direct-sense` 的 `visualSentenceId`、`visualSentenceTextSha256` 与 `sceneQuery` 为空，
但仍必须保存
`teachingSenseId`、`bindingRationale` 和完整资产 receipt。正式实现可以映射到现有
manifest 结构，但不能丢失这些语义和来源字段。

## 6. 代表性例子

下列只是检索与 QA 的示意，不预先指定某一张资产：

| 目标词 | 已批准例句场景示意 | 可见场景查询 | QA 重点 |
| --- | --- | --- | --- |
| `however` | 天在下雨，然而他继续跑 | 雨中继续奔跑的人 | 图中必须同时有阻碍和继续动作 |
| `unless` | 没有钥匙就不能进入 | 钥匙、锁门、准备进入的人 | 图表现条件，不是普通“钥匙”名词图 |
| `otherwise` | 快一点，否则会错过公交车 | 离站公交车与追车的人 | 先后和方向必须清楚 |
| `despite` | 尽管下大雨，她仍去上学 | 雨中走向学校的人 | 阻碍与主动作同时成立 |
| `throughout` | 整个夜里都在下雨 | 从傍晚到清晨的连续雨景 | 需要可见的全时段连续性 |
| `somehow` | 他不知怎么还是找到了出口 | 拿地图的人到达出口 | 只画“出口”不够，需保留过程困难 |
| `nevertheless` | 墙很高，他仍然翻了过去 | 正在越过高墙的人 | 不能只画墙，也不能只画攀爬 |

## 7. QA 门

### 7.1 `direct-sense`

- 不看文件名和例句，图片与首要教学义应有稳定、常见的对应关系。
- 不得只覆盖罕见偏义，也不得靠解释者额外补故事才能成立。
- 64 px 下主体可识别，风格和技术检查沿用 Koboyo 正式资产规则。

### 7.2 `sentence-scene`

- QA 必须查看图片、完整绑定原句和目标词高亮，不能只给 QA 人看裸图。
- 图片准确呈现原句中的可见事实，且不与人数、物体、动作方向、时间或地点冲突。
- 组合后目标词承担的转折、条件、让步、范围等作用比纯文字更容易理解。
- 如果必须补充一句原句中不存在的背景故事才能解释图片，候选失败。
- 如果图片只对应句中的一个普通名词，却没有帮助理解目标词在句中的作用，候选失败。
- 在真实提示卡和 390 px 移动端检查图、句和高亮是否能作为一个单元被读懂。

### 7.3 自动守门

- `direct-sense` 必须拒绝非空的 `visualSentenceId`；`sentence-scene` 必须拒绝缺失或
  无法解析的 `visualSentenceId`。
- 构建时重新计算批准句文本哈希；与 `visualSentenceTextSha256` 不一致即失败关闭，
  防止例句被修改后旧图静默留下。
- 使用视觉的界面测试必须证明 `sentence-scene` 的实际句 ID 与绑定 ID 相同；不相同
  时只能不渲染图片，不能回退到任意图。
- manifest 必须拒绝两个 Entry 因复制记录而意外共享同一个“视觉绑定 ID”；资产文件
  可以在教学义完全一致且记录复用来源时复用，语义绑定记录仍各自独立。

## 8. 当前排除项与以后可能的增强

当前不进入正式生产：

- 以 Koboyo 人物 path 为母版添加道具或重组姿势的 `koboyo-adapted` 图；
- 从空白画布仿画 Koboyo 的独立原创 SVG；
- 批量镜像整个 Koboyo 图库；
- 为配合一张图而改写已批准例句或改变冻结教学义；
- 同一张句义图跨 A/B/C 三条例句复用。

此前两轮仿画试产已证明：技术上能产 SVG，不等于视觉上能融入 Koboyo。除非 Owner
以后看到新的方法或样张并重新授权，这两条路线保持关闭。

若全量统计后仍有少量视觉缺口，可另开决策比较：更换同教学义的批准例句、购买或
引入第二个风格兼容的正版来源、委托人工插画，或为 A/B/C 建立句级多图。它们都不是
本轮默认范围，不能在内容生产中自行开启。

## 9. 完成标准

一个 Entry 只有在以下条件全部满足时，才算完成视觉绑定：

1. `visualMode`、`teachingSenseId`、绑定理由与资产 receipt 完整；
2. `direct-sense` 通过图义 QA，或 `sentence-scene` 通过图句联合 QA；
3. `sentence-scene` 的 `visualSentenceId` 能解析到原样保存且文本哈希一致的批准句，
   所有实际显示界面都遵守同句共现合同；
4. SVG 为逐张选择的未改 Koboyo 原始资产，并通过哈希、解析、安全和小尺寸检查；
5. Owner 在黄金样本中逐张确认语义不牵强，再允许自动推进全量。

因此，“3000 词全部有图”的验收含义是：3000 个 Entry 都有准确的直接词义图，或
有一组不可拆分的准确“原图 + 绑定例句”；不是强迫 3000 个英文词都拥有一张脱离
语境也能被猜中的象形图。

## 10. 首轮试产结果（2026-08-11）

首轮以 `however`、`although`、`throughout`、`unless`、`despite`、`indeed`、
`somehow`、`nevertheless` 八个抽象或关系词验证 `sentence-scene`。Owner 按“未改
Koboyo 原图 + 确切原句 + 目标词高亮”这个不可拆分的 review unit 逐词完成 QA，结果
为 **8/8 合格**。

证据：

- [试产 manifest](../../../data/vocabulary/gaokao-frequency-sentence-scene-pilot-v1.json)
- [Owner QA receipt](../../../data/vocabulary/gaokao-frequency-sentence-scene-pilot-owner-qa-v1.json)
- [逐词 QA 原型](./evidence/sentence-scene-pilot-prototype-v1.html)

这个结果证明：对这组有代表性的抽象关系词，在不修改原图的前提下，用确切例句绑定
可见场景是一条可行路线。它不证明全部 3000 词的视觉缺口已经解决，也不授权把试产
记录接入正式产品；本轮 `integratedIntoProduct` 仍统一为 `false`。
