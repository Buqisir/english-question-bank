# 应用文范文生成准则 v1

Status: production doctrine; implemented by
`prompts/application-writing-model-answer-v3.md`

## 1. 用途与来源

本准则用于指导题库中的高考英语应用文审题、范文生成和独立内容复核。它把
三类依据组合为一个可执行合同：

1. 《普通高中英语课程标准（2017年版2025年修订）》中与应用文直接相关的
   语篇、语用、表达性技能、学业质量与考试评价要求；
2. 朱京力《高考英语应用文审题破解的技巧——从命题底层逻辑到高分写作策略》；
3. 唐邦顺、袁汉邦、赵春丽《高考英语应用文写作的思辨化转型：趋势解读与
   教学策略》。

来源入口见 [`../sources/application-writing/README.md`](../sources/application-writing/README.md)。

本准则是对来源的工程化综合，不替代完整题面、官方答案或评分材料。来源
冲突时，优先级为：完整题面与给定格式 > 官方证据与课标 > 两篇论文 > 本准则。

## 2. 核心判断：应用文是交际任务，不是模板填空

一篇合格范文必须同时回答四个问题：

- 写什么：显性要点、必要背景、任务动作和格式要求是什么；
- 为什么写：希望读者知道、理解、接受、回应或采取什么行动；
- 为谁写：读者身份、与写作者的关系、情感距离和正式程度是什么；
- 如何写：使用什么体裁、信息顺序、论证方式、语气和收束方式最有效。

句式数量、所谓高级词和固定套话都不能替代这四项判断。

## 3. 审题合同

生成前必须从完整题面中锁定以下信息：

1. `form`：载体或体裁，以及必须保留的格式标志；
2. `topic`：题目真正讨论的主题，不只是一两个表面名词；
3. `reader`：显式读者及隐含读者；
4. `person`：主要人称；
5. `tense`：主要时态及必要切换；
6. `type`：任务的主要内容路线；
7. `points`：题面明确要求完成的内容要点；
8. `readerWho`：读者在这个情境中的身份与处境；
9. `readerCares`：读者最关心、最需要判断的信息；
10. `readerWants`：读完后预期获得的理解、回应或行动依据；
11. `value`：本题情境自然支持的意义落点。

这十一项与当前 `ReviewCard` 一一对应。它们是生成决策，不要求写成生硬的
十一句话，也不要求模型公开思考过程。

### 3.1 完整题面优先

- 题面给定的标题、称呼、开头、结尾、敬语和署名必须逐字保留。
- 题面事实、图表信息、参与者身份、时间和地点不得改写成另一情境。
- 不确定某项是不是题面给定时，停止并要求核对，不能自行补成“官方给定”。
- 允许在开放任务中补充合理细节，但细节必须与题面、身份、时空和常识兼容，
  不能伪造官方事实。

### 3.2 主次和信息差

显性要点并不天然等长。详略由三件事共同决定：

1. 哪一项是任务的核心动作；
2. 哪一项最能体现命题的开放性；
3. 哪一项是读者尚不知道、最需要据此理解或行动的信息。

主体要点详写，辅助要点略写。背景句只有在帮助理解主体时才保留。

### 3.3 交际对象推演

`readerWho`、`readerCares` 和 `readerWants` 不能只把读者当作信息接收者。
生成前还要在内部判断：

1. 双方的关系、权力距离、熟悉程度和正式程度；
2. 对方此前是否提供帮助、付出努力、表达善意、提出方案或等待回应；
3. 本文的核心交际动作，以及它是否可能让对方感到被否定、命令、催促、忽视
   或冒犯；
4. 为维持真实关系，是否需要感谢、肯定用意、共情、道歉、缓冲、征求意见或
   邀请回应；
5. 关系动作、核心内容动作和预期回应应按什么顺序出现。

关系动作采用最小充分原则。对方确有具体投入，而本文将提出异议、催促、拒绝
或请求时，优先简短感谢这项具体行为，并可在同一句中肯定其用意；没有真实依据
时不得机械添加感谢或道歉。题面给定开头已经完成的关系动作不得重复，同一种
礼貌功能也不得在开头和结尾重复。

这项推演属于生成决策，不新增 `ReviewCard` schema 字段，也不要求公开模型的
内部审题过程。

## 4. 内容路线

唐邦顺等人的“两类命题”适合作为路由器，不作为不可更改的标签。实际题目
可以是描述型、思辨型或两者混合。

### 4.1 信息或活动描述型

核心问题是 What：发生了什么、具体怎样、有什么可感知或可使用的信息。

推荐内容链：

```text
交际目的 → 核心事实或过程 → 2—3个任务专属细节 → 反应或结果 → 自然收束
```

要求：

- 细节必须能够被看见、听见、想象或核对，例如具体动作、过程、场景特征、
  人物反应和真实结果；
- 细节必须服务要点和主线，天气、心情或背景不能因为“好写”就占据篇幅；
- 感受或意义必须由前文事实支撑，不能用 `meaningful`、`interesting`、
  `learned a lot` 单独冒充内容；
- 结尾完成真实交际，例如邀请回应、询问看法、表达期待或客观总结。

### 4.2 观点、比较或问题解决型

核心问题是 Why / How：为什么这样判断、问题造成什么影响、怎么办。

至少形成一条完整论证链：

```text
观点或问题 → 理由或成因 → 例子 / 机制 / 后果 → 判断或建议
```

要求：

- 先准确界定问题，不把一般不便夸大成严重危害；
- 理由必须说明机制，而不是把“很好、很重要、很有意义”换一种说法；
- 建议必须回应已经指出的问题，并交代预期效果；
- 比较两种选择时使用同一评价标准，不能只赞美所选一方；
- 回应他人方案时，可以先承认合理用意，再指出局限并提出替代办法；
- 论点数量服从词数，宁可一到两条说完整，也不堆三四条空理由。

### 4.3 混合型

先找题目的核心动词和主要采分点，再决定比例。例如“介绍活动并说明推荐
理由”不是把描述和论证各写一半，而是提供足以让读者理解活动的信息，再用
一条具体理由说明为什么值得参加或推荐。

## 5. 证据化内容

朱京力提出的“证据化细节”可以转化为一条通用要求：文章中的判断必须能在
前文找到支撑。

- 描述型的证据是动作、过程、场景、反应和结果；
- 观点型的证据是原因、机制、例子、比较或可预期后果；
- 建议型的证据是问题与建议之间的针对关系；
- 感受型的证据是引发该感受的具体经历；
- 价值落点的证据是文章已经呈现的事实与选择。

每句话至少承担一种功能：完成要点、提供证据、推进逻辑、维持关系或完成
收束。删去没有功能的“正确空话”。

## 6. 结构与连贯

结构不是固定三段式，而是信息功能的顺序。常用顺序包括：

- 目的 → 信息 → 回应；
- 背景 → 过程 → 结果或感受；
- 立场 → 理由 → 例子或结果；
- 问题 → 后果 → 建议 → 预期改善；
- 选择 → 同标准比较 → 结论。

连贯优先依靠意义关系、关键词回扣、指代和信息递进。连接词只在关系需要被
显式标明时使用，不能用 `First, Second, Finally` 掩盖内容之间没有逻辑。

开头提出的核心词必须在主体得到展开；结尾只能收束已经写出的主线，不能在
最后一句突然引入新的宏大主题。

## 7. 得体与读者关系

得体是全文级判断：

- 对同辈：自然、亲切、可以互动，但不假装过度熟悉；
- 对师长、组织者或陌生人：尊重、清楚，提出请求或异议时控制直接程度；
- 对公众：客观、有信息密度，必要时号召或总结，不使用私人书信套语；
- 跨文化交流：避免默认对方知道本地背景，补足必要解释，但不把对方刻画为
  无知者。

礼貌套语本身不等于得体。真正的得体体现在信息选择、请求力度、称呼、句式、
语气和结尾预期回应的一致性。

80词左右的任务中，独立成句的关系动作通常不超过一句；必要的缓冲尽量并入
核心内容句。核心任务已经礼貌完成后，结尾应交代预期改善、邀请自然回应或简洁
收束，不再追加同功能的客套句。

## 8. 价值落点

价值落点必须从题目和内容中自然生长，最多凝练一层。可以是个人认识、关系
改善、共同体价值、文化理解、责任意识或问题解决效果，但不能机械拔高。

两篇论文中的价值分析是解释工具，不是强制答案。特别要遵守：

- 写给外国读者，不自动等于必须弘扬中国文化；
- 出现校园、艺术、自然或劳动，不自动触发固定价值口号；
- 没有内容证据时，不添加“文化自信”“社会责任”等标签；
- 题目只要求信息传递时，高质量、具体、得体地完成信息传递本身就有价值。

## 9. 语言边界

高考能力天花板为课标学业质量水平二。范文目标是水平二的优秀执行：清晰、
得体、连贯、有理有据，而不是展示复杂度。

- 默认使用课标词、高频自然语块和可靠搭配；
- 句式变化按表达需要使用，通常两到三处足够；
- 复杂结构必须压缩信息、突出重点或建立逻辑；
- 对不确定的词、搭配和结构，换成更简单可靠的表达；
- 不用生僻同义词、名言、硬比喻、模板化倒装或中式直译制造“高级感”；
- 词汇是否在范围内与词汇是否在该语境自然，是两道不同的检查。

### 参考范文的篇幅偏好（Owner 2026-09-16）

题面只写“80词左右”时，学生新增正文以110词左右为目标，推荐100—120词；
不为凑字数增加无功能句。确定性验收保留80词下限，上限为120词；较短但内容
充分的成文可接受。给定称呼、开头、落款等仍按既有规则排除，不改变计数口径。
这是本产品的范文编辑标准，不是官方评分线；题面另有明确硬性上限时仍须服从，
由内容复核检查完整题面。其他词数任务不随本次偏好变更。

## 10. 静默质量门

输出前必须逐项检查：

1. 题面事实、格式和所有给定文字是否完整、准确、顺序正确；
2. 显性要点是否全部落地，主体与辅助内容的详略是否合理；
3. 读者是否获得了理解、判断、回应或行动所需的信息；
4. 描述是否有任务专属细节，论证是否有理由和证据，建议是否针对问题；
5. 文章主线是否从开头贯穿到结尾，是否存在无功能句和突然拔高；
6. 语气、直接程度、格式和收束是否匹配读者与场合；
7. 是否以最少必要句子完成情境真正需要的关系动作，并避免无依据或重复的
   机械客套；
8. 每个分句是否有完整主干，时态、语态、主谓一致、名词数、冠词、代词、
   介词、拼写和标点是否可靠；
9. 句式变化是否自然服务意义；
10. 词数是否遵守题面要求，并正确处理题面给定部分；
11. 是否只输出合同要求的成文，没有审题过程、评分、解释或包装。

## 11. 与当前题库合同的关系

- 本准则不改变 `ApplicationWritingAnalysis` schema。
- 当前 `ReviewCard` 的十一项字段继续作为结构化审题结果。
- `modelAnswer` 继续表示 AI 参考范文。
- `officialModelAnswer` 只保存来源真实提供的官方范文。
- 独立内容复核继续作为范文持久化前置门。
- 当前生产 Prompt 为 `prompts/application-writing-model-answer-v3.md`；
  `prompts/application-writing-model-answer-v2.md` 仅保留为上一版历史对照，
  生产工作流不得继续读取 V2。

## 12. 来源使用护栏

- 不把论文中的个别范文、课堂案例或情境判断复制为通用答案。
- 不把论文作者的趋势判断表述成官方评分条款。
- 不从来源项目迁移课程、课堂或学生材料来补充本准则。
- 若准则与新题面冲突，修正准则或转人工确认，不能修改题面来适配准则。
